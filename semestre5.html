Semestre 5

Seguridad del backend, eventos e inscripciones (en curso)

Equipo del semestre

Por ahora el proyecto está a cargo de dos integrantes, que se reparten el desarrollo del backend, la base de datos y la interfaz.

Resumen del semestre

En el quinto semestre convertimos la plataforma en una aplicación segura y funcional: cuentas con roles, gestión de eventos para organizadores e inscripciones para atletas.

Temas clave

  • Autenticación con JWT y autorización por roles
  • Migraciones versionadas de la base de datos (MySQL) y pruebas de integración
  • Validación de datos de entrada y manejo seguro de errores
  • Base de datos de administración separada (SPN_AD)
  • API REST de eventos e inscripciones
  • Contenedores con Docker

Avance del proyecto

  • Inicio de sesión con JWT; la cuenta se comprueba en cada petición, así que una cuenta desactivada o eliminada pierde el acceso de inmediato
  • API de usuarios protegida con permisos por rol y por propietario, y borrado lógico de cuentas
  • Registro e inicio de sesión reforzados: datos validados antes de tocar la base de datos y errores sin detalles internos
  • Registro como Atleta u Organizador
  • Sistema de migraciones versionadas y pruebas de integración contra una base de datos real
  • Línea de administración aparte: alta con un código de un solo uso y login con bloqueo tras cinco intentos fallidos
  • Monitor de carga, limitador de peticiones y prueba de sobrecarga configurable
  • API de eventos y página events.html conectada a la base de datos, con búsqueda, filtros, orden, paginación y detalle
  • Gestión de eventos por parte de los organizadores: crear, editar, cancelar y finalizar
  • Inscripciones de atletas con lista de espera y confirmación o rechazo por parte del organizador
  • Perfil de usuario con foto y entorno de ejecución con Docker
  • Suite de pruebas completa: 133 unitarias, 75 de integración y 30 de la base de administración

Estado actual del proyecto

Tecnologías

  • Frontend: HTML, CSS y JavaScript
  • Backend: Node.js y Express 5
  • Base de datos: MySQL con migraciones versionadas
  • Seguridad: JWT y bcrypt
  • Entorno: Docker
  • Pruebas: ejecutor nativo de Node.js

Decisiones de diseño

  • Los administradores viven en una base de datos aparte, no en la de usuarios
  • No se guarda la IP de los administradores, solo fecha y hora de acceso
  • Un administrador debe tener además una cuenta de Atleta aparte
  • Un organizador puede publicar eventos sin verificación por ahora

Pendiente y próximos pasos

  • Pasarela y verificación de pagos: hoy las inscripciones a eventos con costo quedan pendientes de pago.
  • Interfaz de administración y verificación en dos pasos (2FA).
  • Límite de intentos en el inicio de sesión de usuarios y política de contraseñas.
  • Restringir CORS para producción.
  • Subida de imágenes para las portadas de eventos.
  • Despliegue de la base de datos en Railway y del backend y el frontend en Render.
  • Ampliar las pruebas de edición, cancelación, lista de espera, aprobación manual y pagos.
